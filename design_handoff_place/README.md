## 1. Overview 專案概述

**未寄**是一個給個人使用的「情緒歸位」工具。它每天問一個問題——「今天，有話沒說出口嗎？」——把使用者當下沒說出口的那句話、對象、場合、身體反應記錄下來；累積之後，讓使用者看見自己「對誰特別說不出口」的模式，並提供兩個練習工具（賭注、腳本）幫助下一次真的開口。

核心定位（產品文案基準，請勿改寫成一般心理健康 App 的語氣）：

> 這不是一個記錄情緒的工具，是一個幫情緒**歸位**的工具。

概念來源有二，兩者都會影響 UI 決策，實作時請理解：

- **原點・亞洲家長**：「忍一下就過去了。」情緒不是不被允許，是從來沒有被分配到位置。所以工具不安慰、不評分、不建議。
- **方法・整理術（借用佐藤可士和的整理概念）**：整理不是丟掉，是先問出核心再讓每樣東西回到該在的位置。因此流程固定為三步：**拿出來 → 歸位（對誰／場合／身體）→ 留白**。

四個分頁不是四個功能，是同一個整理動作的四個階段：

| 分頁 | 階段 | 做什麼 |
|---|---|---|
| 今天 | 拿出來 | 記錄今天沒說出口的那句話 |
| 模式 | 歸位後的觀察 | 看出對誰特別說不出口 |
| 賭注 | 校正預期 | 把腦裡演的最壞情況寫下來，事後對答案 |
| 腳本 | 備用 | 整理好的句子，下次直接拿出來用 |

**產品原則（必須遵守，會直接反映在 UI 與文案）：**

1. 不評價、不催促、不給建議、不用驚嘆號、不用表情符號。
2. **不做連續天數（streak）、不做成就徽章、不做推播催促。** 空白的日子不補、不催、不獎勵——留白本身是資訊。
3. 「今天還好」是一個平權的答案，不是跳過。它會被記錄成一筆資料。
4. 所有內容都是私密的，文案要不斷讓使用者感覺「只有你看得到」。

## 2. Naming 命名

**目前暫定：未寄。**

借「未寄出的信」這個既有意象——那句沒說出口的話，就是一封沒寄的信。優點是**不需要解釋**：一秒就懂，而且它描述的是東西本身（一封信），不是容器或動作，帶一點文學感但不煽情。名字裡沒有「情緒」「療癒」「日記」任何一個詞，符合產品不預設使用者有病的立場。

**已知風險（實作時請留意）**：「未寄」會把人的預期拉向書信／日記類 App，可能蓋掉「模式」與「賭注」兩個分頁的功能感。若日後這兩個分頁成為產品重心，名字可能需要重新檢討。因此**產品名務必抽成常數，不要寫死在多處**。

### 其他候選與理由

決策紀錄，供日後重新檢討時參考。共同前提：名字要安靜、要有空間感、不預設使用者有病、不用「療癒／情緒／日記」這類詞。

| 候選 | 理由 | 顧慮 |
|---|---|---|
| **未寄**（現用） | 借未寄出的信，零解釋成本；描述東西本身而非容器 | 易被誤認為書信／日記 App，可能弱化「模式」「賭注」 |
| **半句** | 出自產品自己的文案「話講一半收掉」。半句＝說出口的一半、留在心裡的另一半。兩字、好記、無人使用、比容器類名字多一點溫度 | 抽象，需要一句 tagline 撐（`另外那半句，放這裡。`） |
| **那一格**（原暫名） | 中性的位置隱喻，不帶情緒、不暗示療癒。與 UI 的格狀留白語彙一致 | 需要永遠附帶副標「讓心情有地方放」才成立 |
| **放這裡** | 直接把主按鈕文案升為產品名，最誠實地說明產品做什麼；唸起來像有人在對你說話 | 三個字偏長，較難做成標誌 |
| **擱著** | 台語與國語皆通的日常動詞，語氣等同主按鈕「先放這裡」——不催、不解決、不評價 | 太口語，品牌形象上不夠立得住 |
| **空格** | 「那一格」的近親，多一層排版留白的意思，呼應「留白也是資訊」的原則 | 較冷、較抽象 |
| **留白** | 最貼近佐藤整理術那條線，也最符合不催不獎勵的產品倫理 | 太設計圈，會顯得這是給設計師的工具 |

### 曾評估但排除的方向：咖啡宇宙

曾考慮讓名字掛進既有的咖啡系列（**布粉**——沖煮前把粉撥平讓每顆都在該在的位置，字面上就是整理術；**養豆／靜置**——烘完要靜置排氣，對應不催不獎勵；**悶蒸**——先讓氣跑出來，味道才對）。三者概念貼合度都高，但**對非咖啡族群是零意義的詞**，且會把產品綁進一個與主題無關的品類語境，故暫不採用。若本工具日後確定只在咖啡宇宙內流通，**布粉**是最強候選。

請**在目標專案既有的技術環境中重新實作這些畫面**（React / Vue / SwiftUI / native 皆可），沿用該專案既有的元件庫、狀態管理與樣式慣例。若目前還沒有既有環境，請自行選擇最適合的框架再實作。

不要直接複製原型的 HTML 結構或 inline style 上線——原型為了在單一檔案中即時預覽而採用 inline style，那不是建議的生產寫法。應該把下面「Design Tokens」一節的值落成目標專案的 token / theme 機制。

## 6. 三個互動模型變體 — 該實作哪一個

原型中並列三種方案，供決策用。**建議實作方向：以 1a 的四分頁資訊架構為產品骨架，在窄螢幕（<768px）時，「今天」的記錄流程改用 1b 的逐題模式；1c 作為桌機寬螢幕（≥1200px）的「回顧」進階視圖，可列為第二階段。**

| 變體 | 名稱 | 特性 | 取捨 |
|---|---|---|---|
| **1a** | 紙本分頁式（桌機，900px 寬） | 左側 200px 導覽 + 內容區，四個分頁平權 | 低風險，最接近現有形態 |
| **1b** | 一次一題（手機，400px 寬） | 六步逐題流程，一次只問一件事 | 填寫壓力最低，但回顧速度最慢 |
| **1c** | 回顧工作台（桌機，1080px 寬） | 左時間軸 300px／中詳情彈性／右模式 250px | 最能看出模式，最適合對外展示 |

## 8. Screens 畫面規格

### 共用資料模型

```ts
type Replay = 0 | 1 | 2;            // 0 沒有了 / 1 想過一次 / 2 一直在跑

interface Entry {
  date: string;        // YYYY-MM-DD，每日一筆
  had: boolean;        // false = 「今天還好」
  occasion?: string;   // 場合
  who?: string;        // 對象
  line?: string;       // 那句沒說出口的話
  signals: string[];   // 身體訊號，可複選，可自訂
  replay: Replay | null;
}

interface Bet {
  id: string;
  date: string;
  line: string;        // 如果我把這句話說出口
  bet: string;         // 我賭對方會…（必填）
  when: string;        // 今天之內 / 這週 / 下次見面時 / 不確定
  outcome: 'softer' | 'same' | 'worse' | null;
  note?: string;       // 實際發生的事
}

interface ScriptGroup {
  situation: string;   // 遇到 · <場合>
  lastUsedDaysAgo: number | null;
  lines: string[];
}
```

預設身體訊號（`BASE_SIGNALS`，不可刪）：`臉熱`、`胸口一緊`、`笑著說沒關係`、`話講一半收掉`。
使用者自訂的訊號存入 `customSignals: string[]`，**加入後成為常駐選項，之後每次都出現在預設訊號後面**，並自動勾選於當次記錄。

重播選項（`REPLAY`）：`沒有了` / `想過一次` / `一直在跑`。

### 畫面 1a-1 「今天」— 提問（預設起始畫面）

**目的**：一天只問一個問題，讓使用者用最低成本回答。

**版面**：主內容區左對齊，`max-width: 560px`。

**元件（由上而下）：**

1. **裝飾引號** — 文字 `「　」`（全形引號中夾一個全形空白）。Serif 400 / 64px / line-height 1，`color: var(--rule)`，`letter-spacing: .08em`，`user-select: none`。
2. **主問句** — Serif 400 / 30px / 1.5，`color: var(--ink)`，上下 margin `16px 0 28px`。文案：`今天，` 換行 `有話沒說出口嗎？`
3. **按鈕列** — flex，gap `10px`：
   - 主按鈕「**有**」：`flex: 1`，padding `16px 12px`，`background/border: var(--ink)`，文字 `var(--on-ink)`，Serif 400 / 18px，`letter-spacing: .04em`，radius 2px。
   - 次按鈕「**今天還好**」：`flex: 0 0 128px`，透明底，`border: 1px solid var(--rule)`，文字 `var(--muted)`，Sans 400 / 15px。
4. **說明文** — Sans 400 / 13.5px / 1.95，`var(--muted)`，margin-top `18px`。文案：`沒有也是一筆。不用每天都有東西可寫。`
5. **分隔線** — 1px `var(--rule)`，margin `36px 0 22px`。
6. **最近 N 天條狀圖** — 見下方「共用元件：條狀圖」。

**行為**：點「有」→ 1a-2 記錄表單。點「今天還好」→ 1a-4 完成（今天還好）。

### 畫面 1a-2 「今天」— 記錄表單

**目的**：三個問題完成「歸位」。

## 9. Interactions & Behavior 互動與行為

- **導覽**：1a 分頁切換為即時、無過場（僅內容區進場動畫）。切換分頁時關閉「匯出」小視窗。
- **進場動畫**：所有畫面狀態切換套用 opacity + translateY 6px，`.4s ease`（自訂訊號輸入框為 `.3s`）。**不要加額外的滑動或縮放**。
- **表單驗證**：唯一的必填是賭注的第②欄。記錄表單全部欄位皆可留空——留白是被允許的。
- **鍵盤**：自訂訊號輸入框、新增腳本輸入框皆支援 Enter 送出（需 `preventDefault`）。
- **複製**：腳本「複製」與側欄「匯出 Markdown」使用 `navigator.clipboard.writeText`，失敗時靜默處理，並提供 fallback。
- **hover**：連結由 `var(--accent)` 轉 `var(--accent-hi)`。按鈕與 chip 原型未定義 hover，實作時建議加 `opacity: .85` 或底色微調，不要加陰影或位移。
- **無障礙**：chip 群組請用 `role="group"` + `aria-pressed`；單選群組建議用 radio 語意。所有 icon-free 的純文字按鈕需有清楚可聚焦樣式（建議 `outline: 2px solid var(--accent)`，`outline-offset: 2px`）。
- **響應式**：≥1200px 可用 1c 三欄；768–1199px 用 1a 兩欄（側欄可收合為頂部橫列）；<768px 用 1b 單欄逐題流程，觸控目標最小 44px。
- **深色模式**：跟隨 `prefers-color-scheme`，並提供手動覆寫存於本機。切換僅換 CSS 變數，不改結構。
- **載入 / 錯誤狀態**：本產品為單機本地資料，原型未定義。若實作雲端同步，請沿用同一語氣（例：`還沒同步完，先放著就好。`），不要用「錯誤」「失敗」等字眼。

## 10. State Management 狀態

原型使用的狀態（可直接對應到實作）：

| 狀態 | 型別 | 說明 |
|---|---|---|
| `theme` | `'light' \| 'dark'` | 外觀 |
| `activeTab` | `'today' \| 'pattern' \| 'bets' \| 'scripts'` | 1a 分頁 |
| `todayScreen` | `'ask' \| 'form' \| 'done' \| 'no-done'` | 今天分頁的四種狀態 |
| `draft` | `Entry` | 記錄表單草稿 |
| `entries` | `Entry[]` | 全部記錄（唯一真實來源） |
| `customSignals` | `string[]` | 使用者自訂身體訊號，永久保存 |
| `bets` | `Bet[]` | 賭注 |
| `scripts` | `ScriptGroup[]` | 腳本 |
| `wizardStep` | `0–5` | 1b 逐題流程進度 |
| `selectedDate` | `string` | 1c 時間軸選取日 |

**衍生值（不要另存，由 `entries` 算出）**：對象排行、條狀圖資料、趨勢句、賭注戰績。

**持久化**：全部本機儲存（localStorage / IndexedDB / 原生本機資料庫）。不需要帳號。若日後要同步，資料應加密——文案已多次向使用者承諾「只有你看得到」。

## 13. 給實作者的提醒

這個產品最容易被做壞的地方，是不小心把它做成一般的心理健康 App。請特別避免：

- 加上連續天數、進度百分比、完成率、徽章。
- 把「今天還好」做成灰色的「跳過」。
- 在使用者寫完之後給出鼓勵、分析或建議。
- 用溫暖的漸層、圓潤的大圓角、插畫角色來「柔化」介面。這份設計的溫柔來自留白與文案，不是來自視覺裝飾。

它應該安靜、像一張紙、不催你。
